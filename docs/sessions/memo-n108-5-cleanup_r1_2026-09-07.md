## 3. Ruling 2: Transcribe and Continue to analysis are one action

### 3.1 The rule, and where it lives

`apps/web/src/lib/one-action.ts`, a new file, holds the decision as a pure
function so a gate can pin it. A rule written inside a `.svelte` file is a rule
no vitest in this repository can reach, and this repository already says so.

**AS RIDER 5 LEAVES IT:**

```
transcribeVerdict({ poem, transcribedText, dictionaryReady }, how) -> 'now' | 'soon' | 'wait' | 'nothing'
```

- empty or whitespace field → `nothing`
- `transcribedText === poem` → `nothing`
- dictionary not loaded → `wait`
- `how === 'typing'` → `soon`, else → `now`

**`transcribedText` REPLACED A BOOLEAN, and that is the whole difference between
the 09-04 version and the 09-07 one.** "Has the pipeline run?" was enough while
the only trigger was a score arriving once. Under the widening the question is
"has it run **over this text**", because a singer types, and a stale
transcription of the previous keystroke is the blank-page defect in different
clothes.

**Why there is a `wait` and not just a `no`.** At boot the poem is restored
before `loadDictionary` has finished, so the honest answer at that instant is
"not yet", which is not "never". A singer typing into the field while the
dictionary is still loading lands in the same branch.

**The order of the guards is the rule.** The empty field is asked about first,
so clearing a poem never schedules anything. An up-to-date transcription is
asked about second, so nothing re-runs the pipeline over text it has already
read, which is what makes a boot with a restored transcription, a repeated
`oninput` carrying an unchanged value, and a second arrival all free.

### 3.1a The quiet pause, and what it costs

**DESK DEFAULT: `QUIET_MS = 600`.** Dann asked for "a short pause" and named the
number as the desk's. It is above the ~300 ms a fast typist leaves between
words, so a line is not re-transcribed mid-phrase, and under the ~1 s at which
a pause reads as the app having missed the keystroke. One number, one caller,
one line to change.

**A SECOND DESK DEFAULT, AND IT HAS A REAL COST, so it is named rather than
buried: an implicit run resets the session overrides, exactly as the button
does.** The stress overrides, the ё toggles and the syllable divisions key on
`lineIndex-wordIndex` (`handleStressAssign`), so an edit that adds or removes a
word slides every later position and a kept override lands on a word the singer
never marked. A **dropped** override falls back to the dictionary, which is
right by default; a **stale** one prints a wrong stress on the page. Between
losing a mark and printing a wrong one, this loses the mark.

**What that costs a singer, said plainly.** Set a stress by hand, then fix a
typo in the poem, and the stress is gone. That cost existed before this ship on
every press of Transcribe; rider 5 makes it happen far more often, because now
typing runs the pipeline too. **Keeping a mark across an edit needs stable word
identity, which is exactly N.112.** Dann's to overrule if he would rather keep
the marks and risk the misplacement.

### 3.1b Telling a paste from a keystroke

`IntakePanel.svelte`'s `arrivalOf` reads the `InputEvent`'s own `inputType`
rather than guessing from how much text changed. `insertFromPaste`,
`insertFromPasteAsQuotation`, `insertFromDrop`, `insertFromYank`,
`insertReplacementText`, `insertTranspose`, `historyUndo` and `historyRedo` are
whole; everything else is typing. **Anything it cannot name is treated as
typing**, which is the safe way round: the worst case is a 600 ms pause before
a transcription the singer was getting anyway, where the other way round is the
pipeline running on every keystroke of a long poem.

with their poem sitting in the field.

### 3.3 The button keeps its explicit act

RULED BY DANN 2026-09-07: the button stays and "keeps its explicit act; do not
remove it." So `handleTranscribe` runs the pipeline **unconditionally**, even
where the join has already transcribed this exact text and `transcribeVerdict`
would answer `nothing`. A press that measured the text and decided to do
nothing would be a dead control, and the singer pressed it.

**What this deliberately does not do.** It does not re-seat a score that is
already attached when the poem changes under it. That is **N.112**, the next
item in Dann's sequence, and building it here would be building N.112 early
under another name. The one-action rule fires at the moment a score arrives and
at no other moment.

**The N.57 boot comment is amended, not deleted** (`+page.svelte`, in
`onMount`). It still governs the case it was written for. What changed is that
a boot which finds a poem and a score now transcribes, through `transcribeText`,
where `runPipeline()` runs first and the gloss guard therefore sees the same
words that made the glosses.

## 5. The walk, on a local production build

`pnpm --filter @ilya/web build`, then `vite preview` through `preview_start`.

### 5.1 The instrument, and what could have made it lie

**Every browser surface a Code session has runs its tab with `document.hidden
=== true`**, confirmed again today by reading `document.visibilityState` after
fronting the tab. Chrome clamps `setTimeout` in a hidden tab, the dictionary
loader yields with `setTimeout(0)` every 1500 entries, and the second shard is
therefore never fetched: `Transcribe` never enables, and `canTranscribe` guards
everything downstream. `ENVIRONMENT.md`'s "A HIDDEN TAB" section records this as
the reason every transcription walk since 2026-08-19 has gone to Dann.

**A harness got past it.** A `<script>` gated on `?walkclock`, injected into the
served `index.html`, replaces `setTimeout` for delays of 4 ms or less with a
`MessageChannel` post, which Chrome does not throttle. The dictionary then loads
in about three seconds and `Transcribe` enables.

**What that makes the instrument lie about: timing, and the ordering between a
0 ms timeout and anything else.** It says nothing about what appears on the
page, which is all this walk measures. Nothing about the harness reaches the
source tree; it was removed afterwards and both files were re-checked at zero
occurrences.

**A correction to `ENVIRONMENT.md`, found the hard way and worth an hour to the
next session.** Its §2282 entry says `vite preview` serves `build/` here. **It
does not.** It serves `apps/web/.svelte-kit/output/prerendered/pages/index.html`
and `apps/web/.svelte-kit/output/client/`. The harness and the fixtures were put
in `build/` first and had no effect at all, with nothing on screen saying so;
the older §408 entry, which says preview serves the vite `outDir`, is the
correct one. **A fixture the page must fetch goes in
`apps/web/.svelte-kit/output/client/`, and the server is restarted after it
lands.**

**A second correction: `resize_window` works.** `ENVIRONMENT.md`'s index says it
silently does nothing. Today it took a 1440 × 900 viewport and the desk layout
appeared. Before it, `innerWidth`, `innerHeight` and
`document.documentElement.clientHeight` all read **0**, so
`document.elementFromPoint` returned `null` and no click on the page could raise
the loupe. That is worth knowing on its own: **the loupe cannot be raised from
this pane until the viewport has been sized.**
