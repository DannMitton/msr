## 3. Item 1, the ruling: a deletion moves nothing

**Your words, 2026-09-07:** *"I expected the mnogo to disappear without
affecting the other text underlays."*

Three rules now, and the third is the two others meeting:

- **A deletion vacates its own notes and moves nothing else.** The hole stays
  where the word was.
- **An insert takes open notes only.** An occupied note is left alone and the
  slot goes to the hand, counted in `unseated`.
- **A replacement takes the notes the old word vacated**, in order, however many
  or few there are. Longer, and the surplus slots go to the hand; shorter, and
  the surplus notes stay bare.

**WHAT THE BUILD HAD, AND WHY IT WAS WRONG.** N.112 read Finale's Lyrics window
as authority for a slide: *"delete it, and all the syllables in the score slide
to the left to close up the gap."* That is Finale's behaviour and it was never
put to you, so it was a desk default wearing a citation, which is exactly what
CONTRACT tether 19 exists to catch. Your singer is editing a poem against a line
they have already placed, and a deletion that slides ninety seats undoes an
afternoon.

**Deleted with it:** `closeHole`, the highest-hole-first ordering it needed, and
the `displaced` count. Nothing in this file shifts any more, so no seat can be
pushed off the end of a line by a text edit at all.

## 4. Item 2, the defect: a vacated note is bare in every state

**What you walked:** *"after a Melisma press had pushed one syllable off the
end, deleting много left the last note reading ка ка on both lines."*

**THE CAUSE, and it has two halves.** The gate is `queueExhausted`, which asks
whether every slot of the poem is placed. A melisma press on a seated note
shifts the run forward and pushes the last seat off the end, so one slot is
unplaced from then on, so the gate reads false for ever after and
`vacatedTail` returned an empty set. That is half. The other half arrives with
item 1: with no close-up, a vacated note is usually in the MIDDLE of the run
rather than past the end of it, and a function that looks only past the last
seat would find nothing to blank at all.

**THE FIX IS TWO REGIONS, AND ONLY ONE OF THEM IS GATED.**

- **Inside the run**, between the first seated note and the last, an undecided
  note is vacated ALWAYS, with no gate. That is your own ruling of 2026-09-04 on
  the `ка ка` close you walked then: inside a seated run an undecided note draws
  nothing. Nothing can be waiting to fill it, because the run has passed it.
- **Outside the run**, before the first seat or after the last, the
  `queueExhausted` gate stands unchanged. **It is still the DESK DEFAULT of
  2026-09-07 and still yours to wave off.** With slots unplaced, a note past the
  last seat is one the hand has not reached, and blanking it would take the
  file's words away while you are still working from them.

`vacatedTail` is now `vacatedNotes`, because the tail was never the whole of it.

## 6. Item 4, Undo and Redo as hotkeys

**Your ruling, 2026-09-07:** *"on the desk, Cmd-Z (macOS) / Ctrl-Z executes Undo
as a hotkey."* Shift-Cmd-Z and Ctrl-Y for Redo came with it as the desk default,
and so did the field rule.

- **The same stack the pills use.** The hotkeys call `handleUndo` and
  `handleRedo`, which are the functions the loupe dock and the Corrections
  station already call. A hotkey and a press cannot diverge.
- **Neither fires while a text field has focus**, so the poem keeps the
  browser's own undo. The field guard moved to the top of
  `handleCorrectionKey`, ahead of every branch.
- **It runs with no loupe open**, which is why it sits above the `cursor` test.
  The Undo pill in the drawer has never needed a taken note.
- **An empty stack is not claimed.** With nothing to undo the event is left
  alone rather than swallowed.

**Ctrl-Y is accepted on every platform**, not only on Windows and Linux. On
macOS it is a text-editing binding, and outside a text field there is nothing
for it to collide with. Say if you want it narrowed.

## 9. Two findings, neither of them mine to fix here

**9.1 A clitic re-seat pulls the run back after a melisma has shifted it.** At
step 4 the four vacated notes were bare as expected, but the score-origin seats
from note 36 to the end also moved back by one. The cause is not `reseat.ts`,
which left them exactly where they stood: `reseatAcross` calls `seatCliticFolds`
after the re-seat (`+page.svelte:2213`, N.112), and the melisma's forward shift
had moved the folds off the notes the file seats them on, so the next text edit
pulled them back. **REASONED, NOT MEASURED against the old build:** both
`toggleMelisma`'s shift and that `seatCliticFolds` call are unchanged by N.113a,
so this is on `e1bcb67` too. Step 1, with no melisma in play, moved nothing at
all, which is what says the trigger is the shift and not the deletion.

**9.2 Most seats on this fixture are made from the SCORE's words, not the
poem's.** After Start placement over, 59 of the 96 seats carry
`readScoreText`'s coordinates (`lineIndex 0` with a running `wordIndex`) rather
than the poem's, because `seatCliticFolds` re-seats each fold's run from the
score's own underlay. `reseatByDiff` cannot speak for those seats and leaves
them alone, which is correct and is the `b191867` fix working. **The consequence
is that a text edit does nothing to five of the poem's eight lines on this
file**, including line 7, where `много` lives. That is why the walk above uses
line 3, which is wholly poem-owned. This is not new to N.113a and I have not
touched it. It is worth a number.
